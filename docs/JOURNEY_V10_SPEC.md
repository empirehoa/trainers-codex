# Journey Mode v10 — spec (drafted 2026-08-07)

Everything in this doc is **designed, not yet built**. v9 (live) delivered
levels/XP, the badge track, the box, regional forms, campaigns, stakes/events,
nicknames and saves. This is the next layer, from Jose's 2026-08-07 playtest.

---

## 0. The IP bright line — read first

Jose asked for "key characters from the show/games" and "Team Rocket".
**We cannot use either.** Named characters (Ash, Misty, Brock, Giovanni, Cynthia,
Leon) and named organisations (Team Rocket, Team Magma, Team Plasma) are
trademarked and are exactly the surface TPCi enforces on. This project's whole
survival posture — documented in `JOURNEY_STRATEGY_2026-08.md` §1 and §4 — is
that we ship *no* protected names and *no* official assets.

**What we do instead, which is better anyway:**
- **Original gym leaders and Elite Four**, generated per region from a name
  pool + a type specialty + a difficulty tier. They're procedurally distinct
  per seed, so they're *ours* and they're different every run.
- **An original antagonist syndicate per region** with its own name, motif and
  goal (see §3). Archetype, not homage.
- **The famous-trainer fantasy is preserved** by rank, record and title
  ("the undefeated Ice specialist of the Hoenn circuit"), not by borrowed names.

This is not a hedge — a procedural, original cast is more replayable than a
fixed one, and it's the only version we can legally put a merch funnel behind.

## 1. Gym Leaders → Elite Four → World Cup

### 1.1 Gym leaders (per region, 8)
```ts
interface GymLeader {
  regionId: string;
  index: number;            // 1-8, ascending difficulty
  name: string;             // from an ORIGINAL name pool, seeded
  specialty: PokemonType;
  level: number;            // scales with index and region tour position
  teamIds: number[];        // 3-6 drawn from the region pool, type-filtered
}
```
- Generated by `namedRng(seed, 'gym-${regionId}-${index}')` so they're stable
  per seed and identical for everyone on a daily.
- A gym battle becomes a **chapter with a named opponent** rather than an
  anonymous badge roll. The badge track already exists — this gives each slot
  a face and a type.
- **Type matchup matters**: the player's party types are scored against the
  leader's specialty using the existing `TYPE_CHART`, feeding the chapter's
  win-rate. *This is the payoff for team-building* — the reason to swap and
  evolve becomes concrete.

### 1.2 Elite Four (per region)
- Unlocked at 8/8 badges in a region. Four sequential battles with **no
  healing between them** (party fatigue carries), then a region Champion.
- Clearing it awards a **Region Crown** — a new persistent record, and the
  gate for advancing the tour.
- Failing sends you back to train (costs chapters, not the run).

### 1.3 The World Cup (saga finale)
- Available only at the end of a `saga` campaign with ≥2 Region Crowns.
- Field = every region's Champion + the top-rated gym leaders across the tour +
  **ghost trainers** (§4). Bracket of 16, seeded by score.
- Winning it is the top verdict tier — above `undefeated`.

### 1.4 Where this plugs in
`ChapterPhase` gains `'elite-four'` and `'world-cup'`. `PHASE_PROFILE` gets
entries for both. `resolveChapter` takes an optional `opponent` and folds a
type-matchup term into `winRate`. No architectural change — it's the existing
chapter pipeline with a named adversary.

## 2. Choosing where to travel ("go international")

Today `regionTour()` is derived from the seed. v10 makes it a **player choice**:

- At the end of each region (Elite Four cleared), a **Crossroads decision**
  presents 3 candidate regions, each labelled with *what it offers*:
  "Alola — Alolan forms, Fire/Water specialists, 2 legendaries in pool."
- Implemented as a new `PrepareAction`: `{ type: 'travel', chapterIndex, regionId }`.
  Because actions already replay deterministically, the tour simply becomes a
  function of `(setup, travelActions)` instead of `(setup)` alone.
- **This is the feature that makes team-building intentional** — you go to Alola
  *because* you want an Alolan Ninetales. It pairs directly with the regional
  forms shipped in v9.

`regionTour(setup, actions)` replaces `regionTour(setup)`; `regionAt()` follows.
Everything downstream (pools, badges, gyms) already keys off `regionId`.

## 3. Missions & quests

```ts
interface Quest {
  id: string;
  scope: 'region' | 'campaign';
  titleKey: string; descKey: string;
  goal: { kind: 'catch-type' | 'win-streak' | 'badges' | 'evolve' | 'shiny' | 'defeat-syndicate'; n: number; type?: PokemonType };
  reward: { item?: ItemId; xp?: number; mult?: number; fame?: number };
  progress: number; complete: boolean;
}
```
- **2-3 active at a time**, shown as a compact strip under the badge track.
- Progress is derived from the run state on each replay — no extra mutable
  state, so determinism holds for free.
- **The regional syndicate** is a recurring quest chain: an original org per
  region (name + motif generated from a seeded pool, e.g. "the Ashfall
  Consortium", Fire/Dark motif) that shows up at 3 fixed chapters and must be
  beaten to complete the region cleanly. Beating it grants a rare item and a
  score multiplier; ignoring it costs fame.
- Quest completion is a **Balatro-style "opening"** — a visible near-term goal
  that pays out, which is what keeps a long campaign from sagging.

## 4. Ghost trainers (async competition)

Already recommended by the Aug research as the single strongest retention
mechanic available without netcode.

- On run completion, submit `{ seed, campaign, score, verdict, roster[6], trainerName }`
  to a new `journey_ghosts` Supabase table (anonymous, no PII — same posture as
  `journey_events`).
- Later players on the **same daily seed** face those teams as Elite Four /
  World Cup opponents, labelled "*Nova's team, score 812*".
- Purely additive: with zero ghosts the bracket fills with generated opponents,
  so it degrades cleanly offline and on day one.
- This is also how Jose's "other players' scores included at the end of their
  journeys" lands — their run *becomes* content for the next player.

---

## 5. Encounter rarity (rare / legendary / shiny)

v9 has a rarity-weighted **event** table. v10 extends it to **encounters**:
- Every chapter rolls an encounter tier: common / uncommon / rare / legendary,
  with shiny as an independent low-probability overlay (archetype-modified —
  Shiny Hunter already has `shinyChance`).
- A rare/legendary encounter surfaces as a **decision**: chase it (costs
  fatigue, risks the chapter) or let it go. That's a real choice with a real
  cost, not a free grant.
- Legendary encounters are capped per campaign (1 for short, 2 season, 4 saga)
  so they stay events rather than noise.

## 6. Build order (recommended)

| # | Item | Why first | Est. |
|---|---|---|---|
| 1 | Gym leaders with type matchups | Makes the existing badge track *mean* something and gives team-building its payoff | 1 session |
| 2 | Travel choice (Crossroads) | Unlocks intentional team-building; small change given v9's action replay | 0.5 |
| 3 | Elite Four + Region Crowns | The "keep going until you beat the region" loop Jose asked for | 1 |
| 4 | Quests + regional syndicate | The moment-to-moment goals that carry a long campaign | 1 |
| 5 | Rare/legendary/shiny encounters as decisions | Cheap, high texture, uses existing rarity code | 0.5 |
| 6 | Ghost trainers | Needs a Supabase table + submit path; do after the single-player loop is right | 1 |
| 7 | World Cup finale | Depends on 1, 3, 6 | 1 |

Ship 1-2 together (they're the same subsystem), then 3, then 4-5, then 6-7.

## 7. Non-negotiables carried forward
- Determinism: every new input is a recorded action; the seed link still carries
  setup only.
- No protected names, no official artwork in generated/marketable output.
- `JOURNEY_MERCH_CTA` stays off pending counsel.
- The short campaign must stay ~3 minutes — all of this is opt-in depth, not
  mandatory length.
